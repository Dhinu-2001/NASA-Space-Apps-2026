# API Contract

Status: **Stage 8/9.** Only the endpoints marked IMPLEMENTED exist. Everything else is the planned contract; calling an unbuilt endpoint returns `501 NOT_IMPLEMENTED`.

Machine-readable source of truth: the OpenAPI document generated from the Pydantic models (`docs/openapi.json`, regenerated by `python scripts/export_openapi.py`). The frontend's TypeScript types are generated from it (`npm run gen:api`), so the two sides cannot drift.

## Conventions (all endpoints)

| Topic | Rule |
|---|---|
| Base URL | Backend `http://127.0.0.1:8000`; frontend dev server proxies `/api/*` → backend (prefix stripped) |
| Format | JSON, UTF-8 |
| Time | ISO-8601 UTC with trailing `Z` (e.g. `2027-01-15T00:00:00Z`). Local time is never accepted |
| Angles | Degrees. Longitude **east-positive**, latitude planetocentric (south negative). Azimuth clockwise from local north, 0–360 |
| Lengths | Metres (heights), kilometres only where field name ends `_km` |
| Value labels | Scientific payloads (from Stage 3) carry `data_class`: `measured` \| `calculated` \| `assumed` \| `illustrative` |
| Provenance | Every scientific response carries a `provenance` object: model version, kernel names + SHA-256, DEM product/checksum/resolution/CRS, time step, parameters, assumptions (defined per stage) |
| Request id | Optional request header `x-request-id`; always echoed in the response header and error body |
| Errors | Any non-2xx returns the error body below; no HTML error pages |
| Missing data | Never silently degraded: missing terrain => `DATA_MISSING` / `OUT_OF_DEM_COVERAGE` or an explicit `incomplete` status in the payload |

### Error body

```json
{ "code": "INVALID_INPUT", "message": "…", "field": "lat", "details": {}, "request_id": "ab12cd34ef56" }
```

| code | HTTP | Meaning |
|---|---|---|
| `INVALID_INPUT` | 422 | Malformed/out-of-range input (also request-schema validation) |
| `OUT_OF_DEM_COVERAGE` | 422 | Site/window not covered by available DEM |
| `DATA_MISSING` | 503 | Required kernel/DEM not available locally |
| `EPHEMERIS_OUT_OF_RANGE` | 422 | Time outside supported/validated range (2025-01-01…2035-12-31 validated) |
| `NOT_IMPLEMENTED` | 501 | Endpoint planned but not built in the current stage |
| `INTERNAL` | 500 | Unexpected error (details in server log, correlated by `request_id`) |

## Endpoints

| Method & path | Stage | Status | Purpose |
|---|---|---|---|
| `GET /health` | 1 | IMPLEMENTED | Liveness; model version, env, server UTC time |
| `GET /version` | 1 | IMPLEMENTED | Model/API version, current stage, capability table with honest status |
| `GET /sites` | 2 | IMPLEMENTED | Cited site catalogue (kind: confirmed / intended / candidate), conventions, pending regions |
| `POST /sites/validate` | 2 | IMPLEMENTED | Validate/normalise custom lat/lon; reports DEM coverage (`covered`/`not_covered`) |
| `POST /engineering/solar` | 8 | IMPLEMENTED (validated: owner-approved gate, narrow scope) | Idealised direct-beam solar energy (upper bound) for a site/window and a user-supplied panel (area, efficiency, optional irradiance); position band carried from the visibility result; geometric counterpart; `terrain_data_insufficient` with no figure where terrain data do not support it |
| `GET /provenance` | 9 | IMPLEMENTED | What the running application is built from: code commit, software versions, SPICE kernels and DEM windows with SHA-256, site catalogue and sources, validation fixture, constants, data classes. On a partial install it reports what is missing (`spice_kernels_error`) instead of failing |
| `GET /dem/windows` | 2 | IMPLEMENTED | Extracted DEM windows: extent, pixel size, checksum, validity |
| `GET /dem/elevation?lat&lon[&window_id]` | 2 | IMPLEMENTED | Bilinear LOLA height with provenance; explicit errors, no fallback |
| `POST /ephemeris/series` | 3 | IMPLEMENTED | Sun/Earth az/el/range/light time/angular diameter series for a site (id or lat/lon) over `[start_utc, end_utc]` at `step_seconds`; ≤ 50 000 samples; geometric, no terrain |
| `GET /ephemeris/position` | 3 | IMPLEMENTED | Same for one instant (`time_utc`), `body=sun\|earth\|both` |
| `GET /horizon/profile` | 4 | IMPLEMENTED | Terrain horizon `h(az)` for a site (id or lat/lon) and observer height, with per-azimuth `truncated` / `data_gap` flags, limiting distance and pixel size, cache status and DEM provenance; terrain only, no Sun/Earth |
| `POST /visibility/series` | 5 | IMPLEMENTED | Per-step Sun/Earth states (centre / any-part / fully), geometric vs terrain-corrected, completeness flags, **position sensitivity**, plus transitions, intervals, metrics |
| `POST /visibility/intervals` | 5 | IMPLEMENTED | Same without per-step arrays; `bodies:["sun"]` = solar visibility API, `["earth"]` = Earth visibility API |
| `GET /visibility/at` | 5 | IMPLEMENTED | One instant |
| `POST /scenarios/evaluate` | 6 | IMPLEMENTED | One scenario: `supported` (geometric + terrain-corrected, position bands) or `terrain_data_insufficient` (reason, no numbers); returns a stable `id` |
| `GET /scenarios/{id}` | 6 | IMPLEMENTED | Saved scenario by id (404 `NOT_FOUND` if absent or from another model/DEM) |
| `POST /scenarios/compare` | 6 | IMPLEMENTED | Sites x dates or explicit list; deltas vs baseline with position bands, rankings of supported scenarios only, insufficient sites listed separately |
| `POST /scenarios/delay` | 6 | IMPLEMENTED | Baseline + day offsets; paired deltas with bands, geometric and terrain-corrected |
| `GET /metrics/registry` | 5 | planned | Definition, method, unit, source, assumption, limitation per metric |

### `POST /ephemeris/series` → 200 (Stage 3)

```json
// request
{ "site": { "site_id": "im2-athena" },            // or { "lat": -89.5, "lon": 350, "height_m": 0 }
  "start_utc": "2027-01-15T00:00:00Z", "end_utc": "2027-01-16T00:00:00Z",
  "step_seconds": 900, "bodies": ["sun", "earth"] }
// response (columnar; one entry per sample, aligned with times_utc)
{ "data_class": "calculated", "observer": { "site_id": "im2-athena", "lat_deg": -84.79059, "lon_deg_east": 29.19567,
    "height_m": 0.0, "frame": "MOON_ME", "lat_convention": "planetocentric", "lon_convention": "east_positive" },
  "n_samples": 97, "times_utc": ["2027-01-15T00:00:00Z", "…"],
  "bodies": { "sun": { "azimuth_deg": […], "elevation_deg": […], "range_km": […],
                       "angular_diameter_deg": […], "light_time_s": […] }, "earth": { … } },
  "units": { … }, "notes": [ "Geometric directions of the body centre only; terrain is not applied (Stage 4/5). …" ],
  "provenance": { "model_version": "…", "kernels": [ { "file": "de440s.bsp", "sha256": "…" }, … ],
                  "frame": "MOON_ME", "aberration_correction": "LT+S", "unmodelled": […], … } }
```
Errors: `INVALID_INPUT` (time not UTC-with-Z, bad coordinates/site, step, bodies, > 50 000 samples), `EPHEMERIS_OUT_OF_RANGE` (outside 2025-01-01 ≤ t < 2036-01-01), `DATA_MISSING` 503 (kernels missing/modified). Elevation of the body *centre* only — this is **not** a visibility result.

### `GET /horizon/profile` → 200 (Stage 4)

Query: `site_id` **or** `lat` + `lon`; `observer_height_m` (metres above the DEM surface; **default 2.0 is an assumption, decision C9**, reported as `observer.observer_height_is_default_assumption`); `az_step_deg` (default 0.25, must divide 360); optional `step_m`, `max_range_km`, `use_cache`.
```json
{ "data_class": "calculated_from_measured_interpolated",
  "observer": { "site_id": "im2-athena", "lat_deg": -84.79059, "lon_deg_east": 29.19567, "ground_height_m": 5321.4,
                "observer_height_above_surface_m": 2.0, "observer_radius_height_m": 5323.4,
                "observer_height_is_default_assumption": true, "catalogue_reference_height_m": 5321.0, "frame": "MOON_ME" },
  "n_azimuths": 1440, "azimuth_deg": [0.0, 0.25, "…"],
  "horizon_elevation_deg": [3.51, "…"],         // null where no valid DEM sample exists, never 0
  "horizon_distance_km": [ … ], "limiting_pixel_size_m": [ … ], "range_covered_km": [ … ],
  "n_missing_samples": [ … ], "unseen_bound_deg": [ … ],
  "truncated": [ … ],                            // terrain beyond the DEM edge could still raise the horizon (lower bound)
  "data_gap": [ … ],                             // NoData met on the ray (lower bound)
  "summary": { … }, "units": { … }, "notes": [ "Terrain horizon only … NOT a visibility result …" ],
  "provenance": { "algorithm_version": "1", "observer": { … }, "parameters": { … }, "windows": [ { "window_id": "…", "sha256": "…", "pixel_size_m": 20.0, "source_url": "…" } ] },
  "served_from": "computed" }               // computed | memory | disk
```
Errors: `INVALID_INPUT` (bad site/height/steps, field named), `OUT_OF_DEM_COVERAGE` 422 (no DEM window covers the site or northern hemisphere — **no flat/synthetic fallback**), `DATA_MISSING` 503 (window file missing/modified, or NoData at the observer).

### `POST /visibility/series` and `/visibility/intervals` → 200 (Stage 5)

```json
// request (observer_height_m omitted => 2.0 m default ASSUMPTION, reported)
{ "site": { "site_id": "im2-athena" }, "start_utc": "2027-01-15T00:00:00Z", "end_utc": "2027-02-14T00:00:00Z",
  "step_seconds": 900, "bodies": ["sun", "earth"], "position_uncertainty_m": 100, "n_directions": 8,
  "refine": true, "include_series": true, "az_step_deg": 0.25 }
// response (abridged)
{ "data_class": "calculated", "observer": { "observer_height_is_default_assumption": true },
  "window": { "end_utc": "<last sample>", "step_seconds": 900, "n_samples": 2881 },
  "definitions": { "headline": { "sun": "any_part_visible ...", "earth": "centre_visible ..." } },
  "horizon": { "summary": { "n_truncated": 0 }, "windows": ["im2_20m_r80km", "im2_320m_r160km"] },
  "bodies": { "sun": {
      "headline_state": "any_part_visible",
      "series": { "centre_visible": [], "any_part_visible": [], "fully_visible": [], "headline_visible": [],
                  "geometric_headline_above_local_horizontal": [], "horizon_complete": [], "unverified_visible": [],
                  "position_sensitivity_deg": [], "headline_state_robust_to_position": [] },
      "terrain_effect": { "steps_blocked_by_terrain_only": 155 },
      "completeness": { "visibility_is_upper_bound": false },
      "states": { "centre": {}, "fully": {},
        "any_part": { "is_headline": true,
          "intervals": [ { "start_utc": "...", "end_utc": "...", "open_start": true, "open_end": false, "start_band": null,
                           "end_band": { "earliest_utc": "...", "latest_utc": "...", "width_s": 39908, "complete": false } } ],
          "transitions": [], "metrics": { "total_visible_s": 0, "longest_not_visible_s_closed_only": 0 },
          "position_sensitivity": { "status": "computed", "metric_bands": {}, "boundary_bands": [],
                                    "events_only_in_displaced_runs": 1 } } },
      "headline": {} }, "earth": {} },
  "position_sensitivity": { "status": "computed", "data_class": "calculated",
      "assumption": "observer position uncertain by +/-100 m",
      "kind": "sensitivity of the result to the INPUT observer position; not an error bar on the astronomy or terrain calculation" },
  "limitations": [] }
```
`position_sensitivity.status` is `not_computed` (with `reason`) when the band is 0/null or the terrain data cannot support it (e.g. IM-1: truncated horizon); it is never extrapolated. Errors as for `/ephemeris` and `/horizon` (`INVALID_INPUT`, `EPHEMERIS_OUT_OF_RANGE`, `OUT_OF_DEM_COVERAGE` with no geometric fallback, `DATA_MISSING`).

### `/scenarios/*` (Stage 6)

```json
// POST /scenarios/compare
{ "sites": [{"site_id": "im2-athena"}, {"site_id": "im1-odysseus"}], "start_utc_list": ["2027-01-15T00:00:00Z", "2027-03-15T00:00:00Z"],
  "duration_days": 30, "step_seconds": 900, "position_uncertainty_m": 100, "baseline_index": 0 }
// response (abridged)
{ "scenarios": [ { "id": "<sha256>", "status": "supported", "bodies": { "sun": { "terrain_corrected": { "visible_fraction": { "nominal": 0.486, "band": [0.454, 0.489] }, "events": [ { "time_utc": "...", "band": { "earliest_utc": "...", "latest_utc": "...", "width_s": 0, "complete": true } } ], "longest_not_visible_s": { "including_open": 0, "includes_open_interval": true } },
                                          "geometric": { "visible_fraction": { "nominal": 0.533 } }, "terrain_effect": {} }, "earth": {} } },
                  { "id": "<sha256>", "status": "terrain_data_insufficient", "reason": "...", "note": "No visibility numbers are given ..." } ],
  "excluded_terrain_data_insufficient": [ { "site_id": "im1-odysseus", "reason": "..." } ],
  "deltas_vs_baseline": [ { "delta_band_method": "paired", "bodies": { "sun": { "terrain_corrected": { "visible_fraction": { "delta": -0.061, "delta_band": [-0.064, -0.048], "distinguishable_from_zero": true, "involves_open_interval": false } },
                                                                              "geometric": {}, "summary": [ "sun visible fraction: -6.12 percentage points (band ...; distinguishable from zero)." ] } } } ],
  "rankings": [ { "criterion": "sun_visible_fraction", "ranking": [ { "rank": 1, "nominal": 0.49, "band": [], "distinguishable_from_next": false } ] } ],
  "notes": [], "reading_guide": [] }
```
`POST /scenarios/delay`: `{ "site", "baseline_start_utc", "offsets_days": [1, 3, 7], "duration_days": 14 }` (14 d default is an assumption) returns `baseline`, `delays[{offset_days, scenario, delta_vs_baseline}]`, `summary_table`, `rankings`. Insufficient sites return `status: terrain_data_insufficient` with no numbers.
`delta_band_method`: `paired` (same site: difference per displacement, one shared position error) or `independent_interval_arithmetic` (different sites, conservative). Any metric involving an interval cut off by the window edge is flagged `involves_open_interval`.

### `POST /engineering/solar` -> 200 (Stage 8)
Request = a `/scenarios/evaluate` request (`site`, `start_utc`, `duration_days`, ...) plus `area_m2` (required, (0, 10000]), `efficiency` (required, (0, 1]) and optional `irradiance_w_m2` ([1000, 1500]; the default 1361 is an assumption). Response (abridged): `{ data_class: "calculated", kind: "idealised direct-beam solar energy: an UPPER BOUND, not a power budget and not battery state", panel: { area_m2, efficiency, irradiance_w_m2, irradiance_is_default_assumption, peak_electrical_power_w, formula }, window_hours, terrain_corrected: { energy_wh: { nominal, band }, mean_power_w, sunlit_hours, longest_without_direct_sunlight: { hours, band_hours, includes_open_interval } }, geometric: { energy_wh, mean_power_w, sunlit_hours }, terrain_effect: { energy_wh_terrain_minus_geometric }, partial_disc_bracket: { whole_disc_energy_wh, any_part_energy_wh }, position_sensitivity, assumptions, limitations, provenance }`. Errors: `INVALID_INPUT` (field named: `area_m2`, `efficiency`, `irradiance_w_m2`, or a site/window field). For a site without terrain support: `{ status: "terrain_data_insufficient", reason, reason_code }` and no energy keys. `POST /engineering/antenna` (deferred) returns `501`.

### `GET /version` -> 200

```json
{ "model_version": "0.10.0-stage8", "api_version": "0.1.0", "stage": 3,
  "notice": "Stage 3: site catalogue, DEM elevation lookup and geometric Sun/Earth ephemeris. No terrain horizon or terrain-corrected visibility results are produced yet.",
  "capabilities": [ { "key": "dem", "title": "…", "stage": 2, "status": "implemented_unvalidated" } ] }
```
Capability `status` ∈ `not_implemented` | `implemented_unvalidated` | `validated`. The UI must display this status; it may not present a capability as available unless `validated`.

### Planned scenario request (draft, finalised in Stages 5–6)

```json
{ "site": { "lat": -89.5, "lon": 0.0 }, "start_utc": "2027-01-15T00:00:00Z", "duration_days": 30,
  "step_minutes": 15, "observer_height_m": 2.0, "earth_elevation_mask_deg": 0.0 }
```
`observer_height_m` default 2.0 is an **assumption** (decision C9). Scenario identity = SHA-256 of the canonical JSON of the request plus `model_version` (decision C5).

## Versioning
`api_version` follows semver; contract-breaking changes bump the minor version while 0.x. `model_version` changes whenever any calculation changes and is stamped into every result.
